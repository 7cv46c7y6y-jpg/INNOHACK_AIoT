## 1. 한 줄 요약

피해 양식어업인이 기록을 한 번 입력하면, 어업인이 직접 써야 하는 공식 서식 3종의 초안(HWPX)을 만들고, 누락·오류·기한 위험을 알려 주며, 입력한 피해를 가두리 단위 지도로 보여 주는 웹 서비스.

**원칙: 넣기로 한 기능은 끝까지 제대로 동작해야 한다. 일부만 동작하는 기능은 넣지 않는다.**

## 2. 문제와 배경

### 2.1 어업인이 겪는 문제

- 고수온 같은 재해가 나면 피해 어업인은 서로 다른 법령의 서식 3종을 따로따로 써야 한다. 주소·성명·면허번호·품종·면적·어장 위치처럼 같은 값을 서식마다 다시 적는다.
- 서식 안에는 어업인이 쓰는 칸과 담당 공무원이 쓰는 칸(회색 칸)이 섞여 있다.
- 놓치면 지원에서 빠지는 조건이 있다.
  - 피해 발생 사실을 지체 없이 신고한 어가만 어업재해 조사 대상이 된다.
  - 양식업 재난지원금은 재난 전에 입식·출하·판매 신고를 해 둔 경우에만 지급된다.
  - 재난지원금 신고(① + ③)는 재난이 끝난 날부터 10일 이내에 해야 한다.

### 2.2 기존 방법의 한계

- 종이·한글 서식을 하나씩 작성하다 보니 반복 입력, 단위 혼용, 서식 간 값 불일치가 생긴다.
- 기한과 선행 조건이 여러 법령에 흩어져 있어 어업인이 스스로 확인하기 어렵다.
- 주변 가두리의 피해 상황을 한눈에 볼 방법이 없다.

### 2.3 왜 동남권인가

- 경남 남해안(통영·거제·고성·남해·하동)은 해상가두리 양식이 많고 고수온 피해가 반복되는 지역이다.
  - 2021년 해수부는 이 5개 시·군 69개 어가에 고수온 피해 1차 복구 지원을 의결했다.
  - 2026년에도 경남을 포함한 4개 시·도 338개 어가에 대한 "1차 고수온 어업재해 복구 지원 계획"이 확정됐다.
- 시연 시나리오와 지도의 가상 데이터는 통영 해역을 기준으로 만든다.

## 3. 목표와 하지 않는 것

### 3.1 목표

- **G1.** 한 번 입력으로 어업인이 쓰는 서식 3종(②①③)의 HWPX 초안을 만든다.
- **G2.** 계산 결과(재해 직전 사육량, 피해율)와 누락·오류·기한·선행 조건의 위험을 보여 준다.
- **G3.** 서명, 공무원 확인, 동의처럼 사람이 직접 해야 할 일을 구분해서 안내한다.
- **G4.** 입력한 피해를 가두리 단위 지도에 표시한다.

### 3.2 하지 않는 것 (v1 범위 밖)

- 보험금 산정, 공적 피해액·피해 원인 확정, 수협 보험금청구서 작성 (원본 미확보)
- 서명·도장 생성, 담당 공무원 칸(회색 칸) 작성
- 실제 접수·제출 대행
- ④ 양식생물 피해조사 서식 작성 (조사반이 쓰는 서식이므로 준비 안내만 한다)
- AI 값 추출, 공공 수온 API, 주소 검색 API
- 주민등록번호·계좌번호 수집
- 로그인, 데이터베이스

## 4. 사용자와 시연 시나리오

- **주 사용자**: 해상가두리 어류 양식어가
- **함께 쓰는 사람**: 대신 신고하는 사람(가족·이장·통장·이웃, ① 서식에서 허용), 작성을 돕는 어촌계·수협 직원
- **시연 시나리오 (모두 가상)**
  - 통영의 가상 양식어가, 품종 조피볼락, 고수온 의심 피해
  - 입식 100,000마리, 기존 출하 7,000마리, 기존 폐사 3,000마리
  - 재해 직전 사육량 90,000마리, 이번 폐사 추정 12,000마리, 피해율 13.33%

## 5. 대상 서식과 처리 범위

| 서식 | 원본 형식 | 작성자 | 시기와 제출처 | 앱이 하는 일 |
|---|---|---|---|---|
| ② 어업피해발생신고서 (어업재해 피해조사·보고 및 복구지원 요령 별지 제1호) | HWPX, 1쪽 | 피해 어업인 | 피해가 나면 지체 없이, 관할 읍·면·동장 | 자동 작성 |
| ① 자연재난 피해신고서 (자연재난 구호 및 복구 비용 부담기준 등에 관한 규정 별지 제1호, 2025.11.27 개정) | HWP, 3쪽 | 신고인. 회색 칸은 담당 공무원 | 재난이 끝난 날부터 10일 이내, 시장·군수·구청장 | 자동 작성 |
| ③ 어류 등의 입식 및 출하·판매 신고서 (같은 규정 별지 제2호, 2021.6.1 개정) | HWP, 1쪽 | 신고인·어업권자 | 평소: 입식 후 20일 이내, 출하·판매는 다음 달 5일까지. 피해 신고 때: ①과 함께 매매전표·수산종자 구입 서류를 붙여 제출 | 자동 작성 + 재난 전 신고 여부 확인 |
| ④ 양식생물 피해조사(가두리/어류) (요령 별지 제3호) | HWPX | 피해정밀조사반 (어업인은 참여·협조) | 신고 후 정밀조사 때 | 조사 준비 안내만 |

참고: 장기 여행 같은 부득이한 사유로 기간 안에 신고하지 못했다면, 그 사유가 끝난 날부터 10일 이내에 신고할 수 있다 (규정 제9조 제6항).

## 6. 사용자 흐름

홈의 **피해보상 서류 작성** 버튼을 누르면 작성 화면 한 페이지에 아래 1~7이 카드로 차례대로 나온다. 오른쪽에는 요약(재해 직전 사육량, 폐사량, 피해율, 첨부 수)과 **검토하고 서식 받기**·시연 데이터로 채우기·입력 지우기 버튼, 바로 가기가 따라다닌다.

1. **재해 정보**: 재해 종류, 피해 발생일, 재난 종료일(예: 고수온 특보 해제일, 모르면 비움)을 입력하면 신고 기한을 계산한다.
2. **어가·면허·양식장 정보**: 서식 3종에 공통으로 들어가는 값을 한 번만 입력한다.
4. **사육 기록**: 입식, 출하·판매, 기존 폐사, 사료 구입을 행 단위로 입력한다.
5. **피해 정보**: 이번 폐사량, 피해 기간, 응급조치, 원인 설명(추정)을 입력한다.
6. **① 서식 전용 질문**: 주거 형태, 가족 수, 고등학생 수, 연락처, 간접 지원, 확인 사항을 묻는다. 모르면 "모름"을 고르고 빈칸으로 둔다.
7. **증빙 서류 첨부**: 항목별(피해 사진, 매매전표, 수산종자 구입 서류, 면허증 사본, 사료 영수증, 현장 측정 기록, 응급조치 기록)로 파일을 붙이거나 "종이·원본으로 가지고 있음"에 체크한다.
8. **검토와 받기**: 오른쪽 **검토하고 서식 받기**를 누르면 맨 아래에 검토 결과가 나타난다. 계산 결과, 오류(누르면 그 칸으로 이동), 미확인 항목, 기한, 서명·공무원 칸·동의 안내를 보여 주고, 서식을 하나씩 또는 **제출 묶음**(서식 3종 + 증빙 + 제출목록)으로 내려받는다.
9. **지도**: 내 가두리와 다른 (가상) 어가의 피해 현황을 본다.

## 7. 기능 요구사항

### FR-1 공통 입력

- 여러 서식에 들어가는 값은 한 번만 입력하고, 서식 3종에 같은 값을 쓴다.
  - 공통 값: 성명, 주소, 연락처, 면허(허가)번호, 면허기간, 면허 면적, 품종, 어장 위치, 시설방법
- 필수·선택 여부를 표시하고, 각 질문에서 "모름"을 고를 수 있다. "모름"은 서식에서 빈칸이 되고 미확인 항목 목록에 오른다.
- 주민등록번호·계좌번호 입력란은 만들지 않는다. 서식의 해당 칸은 빈칸으로 두고 "다운로드 후 직접 기입"이라고 안내한다.
- 시연 서버이므로 실제 개인정보를 넣지 말라는 안내를 모든 화면 아래(바닥글)에 표시한다.

### FR-2 계산

- 재해 직전 사육량 = 입식 − 출하 − 기존 폐사 (마리)
- 피해율(%) = 이번 피해량 ÷ 재해 직전 사육량 × 100, 소수 둘째 자리까지 반올림
  - 요령의 양식수산물 피해 기준(피해 당시 사육 물량 대비 피해물량)과 같은 정의다.
  - 참고값이며 공적으로 확정된 값이 아님을 함께 표시한다.
- 신고 기한
  - ②: "지체 없이"로 표시한다.
  - ①③: 재난 종료일 다음 날부터 세어 10일째 되는 날. 그날이 토·일요일이나 공휴일이면 다음 평일로 한다.
  - 계산한 날짜는 "참고 기한이며 지자체 공고가 우선"이라고 함께 표시한다.

### FR-3 검증

- 필수값 누락
- 0 이하 또는 음수 수량
- 이번 피해량이 재해 직전 사육량보다 큰 경우
- 날짜 순서 오류 (예: 입식일이 피해 발생일보다 늦음)
- 단위 혼용 방지: kg와 마리, 원/마리와 천원은 서로 다른 입력칸으로 받는다
- ③ 표의 "계"와 각 행 합계 불일치
- 같은 입력에는 항상 같은 계산 결과와 같은 오류 안내가 나온다

### FR-4 ② 어업피해발생신고서 생성

- 채우는 칸: 피해어업권자 주소·성명, 면허(허가)번호, 품종, 면적, 면허(허가)기간, 어장 위치, 피해 원인, 피해발생기간, 피해 상황, 응급조치사항, 기타 사항, 신고일, 신고자 주소·성명
- 피해 원인 = 신고인이 쓴 설명 + "(추정)"
- 피해 상황 = 피해량(마리) + 피해율 참고값. 피해액은 사용자가 근거와 함께 입력한 경우에만 적고, 아니면 "미확인"
- "(인)" 자리는 비운다.
- **완료 기준**: 한글에서 열리고, 1쪽이 유지되며, 원본 문구가 그대로이고, 겹치거나 잘린 글자가 없다.

### FR-5 ① 자연재난 피해신고서 생성

- 원본 HWP를 HWPX 템플릿으로 변환해서 쓴다. 원본의 3쪽 구성, 표, 회색 칸, 서명 위치를 그대로 보존한다.
- 채우는 칸
  - 1. 피해자 정보 (주민등록번호·계좌번호 제외)
  - 2. 피해 내용 중 신고인 칸: 피해 발생 위치, 피해시설명, 총면적, 면허·허가·등록 번호, 피해물량 신고, 간접 지원 체크
  - 3. 간접 지원, 4. 확인 사항
  - 신고일, 신고인 성명, 피해자와의 관계
- 채우지 않는 칸: 접수번호·접수일·처리기간, 피해물량 확정, 피해 구분, 피해 원인, 담당 공무원 확인 사항, 모든 서명란. 3쪽 동의란은 이름도 쓰지 않는다 (동의는 본인이 직접 서명해서 표시하는 방식이다).
- 시설 번호 ①~⑩의 대응 관계를 지킨다. 시연에서는 시설 1곳만 쓴다.
- `[  ]` 칸은 사용자가 고른 항목만 `[√]`로 바꾼다.
- 좁은 칸은 줄을 바꾸지 않고 글자 크기를 줄여서 맞춘다.
- **완료 기준**: 한글에서 3쪽이 유지되고, 겹치거나 잘린 글자가 없으며, 회색 칸과 서명란이 비어 있다.

### FR-6 ③ 입식·출하·판매 신고서 생성

- 원본 HWP를 HWPX 템플릿으로 변환해서 쓴다.
- 채우는 칸: 신고인, 어업권자·양식업권자(행사자), 어업의 종류, 시설방법, 어업권 현황, 입식 표, 출하(판매)·폐사 표, 그 밖의 사항(수산종자 구입처, 판매일시, 연락처, 판매처), 사료 구입 표, 신고일
- 표 행 수는 원본 그대로다: 입식 4행 + 계, 출하·폐사 4행 + 계, 사료 2행. 이보다 많이 입력하려 하면 입력할 때 막고 안내한다.
- 출하와 폐사를 같은 표에 적으므로, 폐사 행은 품종 칸에 "(폐사)"를 붙이고 판매단가·금액은 비운다. (가정이며 규칙 파일에서 바꿀 수 있다.)
- 단위는 크기(cm·g), 수량(kg), 마리 수, 판매단가(원/마리), 금액(천원), 잔량(마리)으로 나눈다.
- "재난 전에 이 신고를 했나요?"를 예/아니오/모름으로 묻는다. 아니오나 모름이면 "재난지원금 대상에서 빠질 수 있음"을 경고하고, 이 서식을 지금 만들어도 과거 신고 이력을 대신하지 못한다고 안내한다.
- **완료 기준**: 한글에서 1쪽이 유지되고, "계"가 각 행의 합계와 같으며, 겹치거나 잘린 글자가 없다.

### FR-7 ④ 조사 준비 안내와 증빙 체크리스트

- 조사 준비는 증빙 항목의 "조사 준비" 표시(피해 사진, 현장 측정 기록, 응급조치 기록)와 홈의 신고 순서로 안내한다. 검토 화면에 따로 긴 목록을 두지 않는다 (v1.4).
- 증빙 7항목(피해 사진, 매매전표, 수산종자 구입(생산) 서류, 면허증 사본, 사료 구입 영수증, 현장 측정 기록, 응급조치·사료 공급 기록)마다 파일을 첨부하거나 "종이·원본으로 가지고 있음"에 체크한다. 파일을 붙이면 준비된 것으로 본다. 둘 다 없는 항목은 "준비 필요"로 표시하고 검토 화면과 제출목록에 올린다.
- ③에 붙이는 서류(매매전표, 수산종자 구입 서류)와 조사 준비 자료(사진, 측정 기록, 응급조치 기록)를 항목에 표시한다.
- 행정정보 공동이용에 동의하지 않으면 주민등록표 등본·소득금액 증명·가족관계증명서를 직접 내야 한다는 점을 "직접 하셔야 할 일"에 한 줄로 안내한다.

### FR-8 검토 화면

- 화면에서는 서식을 ①②③④ 번호 대신 이름(어업피해발생신고서, 자연재난 피해신고서, 입식·출하·판매 신고서, 양식생물 피해조사 서식)으로 부른다. 이 문서의 번호는 팀 안에서 쓰는 약칭이다.
- 꼭 필요한 것만 보여 준다 (v1.4): 계산 결과와 기한(②는 "지체 없이", ①③은 계산한 날짜), 먼저 고쳐야 할 오류, 서식 받기.
- 꼭 필요한 나머지는 빨간 상자 하나에 모은다.
  - 제출 전에 꼭 확인하세요: 경고(지체 없이 신고, 품종 불일치, 준비 안 된 증빙, 재난 전 신고 여부, 기한 지남 등)와 칸에 다 들어가지 않은 값
  - 직접 하셔야 할 일: 주민등록번호·계좌번호 직접 기입, 서명 위치(① 6곳: 2쪽 신고인 1곳·3쪽 동의 5곳, ② 1곳, ③ 1곳), 행정정보 공동이용 미동의 시 낼 서류, 서식에 채우지 못한 곳(빈칸·'미확인')
- 보여 주지 않는 것: 글자를 줄여 칸에 맞춘 알림(넘친 경우만 알림), 피해율 참고 문구(위 숫자와 중복), 회색 칸 안내, 동의 5가지 표, 피해조사 준비 목록

### FR-9 다운로드

- 서식별 HWPX를 하나씩 받거나, 3종을 묶음(zip)으로 받을 수 있다.
- 파일 이름에 "초안"을 표시한다 (예: `초안_자연재난피해신고서_20261127.hwpx`). 원본을 보존하기 위해 서식 본문에는 문구를 추가하지 않는다.
- 생성한 파일은 서버에 저장하지 않는다.
- **제출 묶음(zip)**: 서식 3종과 첨부한 증빙, 제출목록을 한 파일로 받는다.
  - `1_서식(서명 전 초안)/` 서식 3종 HWPX
  - `2_증빙/01_피해사진/`, `02_매매전표/` … 항목별 폴더에 첨부 파일 (같은 이름은 "(2)"를 붙임)
  - `제출목록.txt`: 서식별 제출 시기·기관·참고 기한, 칸 맞춤으로 글자를 줄인 곳, 계산 결과, 첨부한 증빙과 아직 없는 증빙, 직접 할 일, 확인할 것, 미확인 항목
- 첨부 제한: 합계 20MB, 30개까지. 사진(jpg·png·heic 등), PDF, 한글(hwp·hwpx), 워드, 엑셀, csv, txt만 받는다. 브라우저에서 먼저 막고 서버에서 다시 확인한다.
- 첨부 파일은 묶음을 만들 때만 서버로 보내고 메모리에서 처리한다. 서버에 저장하지 않는다.
- zip 안 파일 이름은 Windows 탐색기의 "압축 풀기"에서 깨지지 않게 CP949로 쓰고, 7-Zip·반디집·macOS·리눅스용으로 UTF-8 이름(Info-ZIP Unicode Path, 0x7075)도 함께 넣는다. 첨부 파일 이름에서 CP949에 없는 글자(이모지 등)는 "_"로 바꾼다.

### FR-10 가두리 피해 지도

- Leaflet + OpenStreetMap을 쓴다 (키 불필요, 인터넷 필요).
- 마커 색은 폐사율 구간으로 나눈다: 10% 미만 / 10~30% / 30% 이상.
- 마커를 누르면 품종, 폐사율, 수온, 측정 일시, 기록일을 보여 준다.
- 통영 해역 가상 어가 7곳을 미리 넣어 두고 이것만 보여 준다 (`data/seed_farms.json`). 화면에 "시연용 가상 데이터"라고 알린다.
- 작성 화면에서는 가두리 위치를 받지 않으므로 작성한 피해를 지도에 올리는 기능은 두지 않는다 (v1.4).
- 지도에는 이름·주소·면허번호 같은 개인 식별 정보를 표시하지 않는다.

### FR-11 화면 구성

- 화면 디자인은 Sneat 무료 관리자 템플릿(Bootstrap 5, MIT)을 쓴다. 카드 구성을 따른다. 왼쪽 메뉴(홈, 피해보상 서류 작성, 피해 지도)는 지도 화면에만 두고 홈과 작성 화면에는 두지 않는다. 위쪽 바는 두지 않는다. 휴대폰·태블릿 화면에서는 왼쪽 메뉴가 숨으므로 "메뉴" 버튼만 둔다. Public Sans에는 한글이 없어 맑은 고딕·Apple SD Gothic Neo·Noto Sans KR로 이어지게 한다.
- **홈** (`/`): 서비스 이름과 피해보상 서류 작성 버튼, 신고 순서, 서식 3종 카드(기한 배지) 순서. 지도와 피해 현황 숫자는 피해 지도 화면에만 둔다. 노트북 화면(1920×1080, 배율 125%, 브라우저 안쪽 약 1536×700)에서 스크롤 없이 한 화면에 들어오게 하고, 화면이 더 길면 카드 세 줄이 높이를 나눠 채워 아래가 비지 않게 한다.
- **피해보상 서류 작성** (`/apply`): 6장의 흐름 1~8을 한 페이지에 둔다. 단계 제목은 색을 채운 막대로 보여 단계마다 구분한다. 오른쪽 바로 가기 아래에 뒤로가기 버튼을 둔다 (사이트 안에서 왔으면 이전 화면, 주소를 직접 열었으면 홈. 입력한 내용이 있으면 사라진다고 한 번 묻는다). 검토 버튼은 오른쪽 요약 카드에만 두고, 누르면 맨 아래에 검토 결과 카드가 나타난다. 시연 데이터 버튼도 요약 카드에만 둔다. 오른쪽 요약은 화면을 내려도 따라온다. 휴대폰에서는 요약이 맨 아래로 간다.
- **피해 지도** (`/map`): 지도, 폐사율 구간, 요약

## 8. 서식 기재 규칙 (기본값)

공식 작성 예시를 찾지 못해 정한 기본값이다. `config/form_rules.json`으로 분리해서, 지자체 확인 결과가 나오면 코드를 고치지 않고 바꾼다. 화면에는 "가정"이라고 표시한다.

### ① 자연재난 피해신고서

- 피해 발생 위치 = 어장 위치 (①~⑤, ⑥~⑩ 묶음마다 한 칸)
- 피해시설명 = "해상가두리"
- 총면적 = 면허 면적(ha)
- 면허·허가·등록 번호 = 면허증 번호 그대로
- 피해물량 신고 = 마리 수 (예: "① 12,000마리")
- 품종은 "피해 발생 위치" 칸에 함께 적는다 (예: "… 지선 해상 (품종: 조피볼락)"). 시설별 칸은 폭이 약 2.4cm라 "품종 + 마리 수"는 6pt로 줄여도 한 줄에 들어가지 않는다 (v1.1, 구현 중 확인)
- 주거 형태, 가족 수, 고등학생 수, 통신사, 도시가스, 자동차 같은 일반 항목과 국·공유재산 사용·대부 여부는 직접 묻고, 모르면 빈칸

### ② 어업피해발생신고서

- 피해 원인 = 신고인 설명 + "(추정)" (공식 원인이 아님을 화면에 표시)
- 피해 상황 = 피해량(마리 수) + 피해율 참고값. 피해액은 근거와 함께 입력한 경우에만, 아니면 "미확인"
- 응급조치 = 사용자 입력 그대로 (예: 액화산소 공급, 사료 공급 중단)

### ③ 입식·출하·판매 신고서

- 입력한 기록을 그대로 옮기고, 서식의 단위 구분을 섞지 않는다.
- 폐사 행은 품종 칸에 "(폐사)"를 붙인다.

### 공통

- 서명·도장·공적 확인 결과는 만들지 않는다.
- 모르는 값은 빈칸으로 두고 "미확인 항목" 목록에 넣는다.
- 주민등록번호와 계좌번호는 받지 않는다.

## 9. 비기능 요구사항

- **개인정보**: 주민등록번호·계좌번호는 받지 않는다(개인정보 보호법상 주민등록번호는 법령 근거가 있을 때만 처리할 수 있다). 생성한 서식 파일과 첨부한 증빙은 서버에 저장하지 않는다. 지도에는 개인 식별 정보를 표시하지 않는다. 시연 서버에는 가상 데이터만 넣는다.
- **배포**: 무료 호스팅에 시연용으로 공개 배포한다. main 브랜치를 기준으로 한다.
- **호환성**: 생성한 HWPX는 한컴오피스 한글에서 열려야 한다. 팀의 윈도 노트북에 설치된 한글로 확인한다.
- **실행 환경**: 로컬은 Python 3.14(윈도), 서버는 Python 3.10 이상
- **화면**: 휴대폰 화면 폭에서도 입력할 수 있어야 한다. 입력은 한 페이지에서 순서대로 하고, 오른쪽 요약과 바로 가기로 위치를 잡는다.
- **오프라인**: 지도 바탕은 인터넷이 있어야 보인다. 서식 생성은 로컬에서 실행하면 인터넷 없이도 동작한다.

## 10. 기술 구성

- **웹**: Flask, Jinja2 템플릿, HTML·CSS·JS, Sneat(Bootstrap 5) 화면 템플릿, Leaflet

- **쓰지 않는 것**: pyhwp를 거친 ODT 변환(3쪽이 6쪽으로 깨짐), LibreOffice(HWPX를 열지 못함)
- **저장**: 지도용 JSON 파일 (`data/`)

## 11. 서식 ① 구조 메모 (원본 분석 결과)

- 쪽마다 큰 표가 하나씩 있다: 1쪽 36행×18열, 2쪽 19행×6열, 3쪽 40행×16열
- 회색 칸: 접수번호·접수일·처리기간, 피해물량 확정, 피해 구분, 피해 원인 (①~⑩ 모두)
- 피해 발생 위치는 시설마다가 아니라 ①~⑤, ⑥~⑩ 묶음마다 한 칸이다.
- 시설별 칸은 폭이 약 2.4~2.8cm이고 글자가 9pt라서, 한 줄에 한글 7자 안팎이 들어간다(추정).
- 1쪽 표가 쪽을 꽉 채우고 있어서, 줄이 바뀌어 행이 길어지면 표가 2쪽으로 밀려 3쪽 구성이 깨질 수 있다.
- 서명 위치는 6곳이다: 2쪽 신고인 1곳, 3쪽 동의 5곳(행정정보 공동이용 1, 개인정보 수집·이용 1, 제3자 제공·활용 3).

## 12. 완료 기준 (전체)

1. 시연 시나리오를 입력하면 서식 3종 HWPX를 내려받을 수 있다.
2. 한글에서 세 파일이 모두 열리고, ① 3쪽·② 1쪽·③ 1쪽이 유지되며, 겹치거나 잘린 글자가 없다.
3. 회색 칸, 서명란, 주민등록번호·계좌번호 칸이 비어 있다.
4. 재해 직전 사육량 90,000마리, 피해율 13.33%가 정확히 나온다.
5. 누락, 음수, 피해량 초과, 날짜 역전, 합계 불일치를 각각 넣으면 경고가 나온다.
6. 지도에 가상 어가 7곳이 표시된다.
7. 증빙을 첨부하면 제출 묶음의 항목별 폴더에 들어가고, 제출목록에 첨부한 것과 빠진 것이 정리된다. 허용하지 않는 형식과 20MB 초과는 막힌다.
8. 배포한 링크에서도 같은 흐름이 동작한다.
9. 일부만 동작하는 기능이 없다.

## 13. 구현 순서

0. ①③의 HWP → HWPX 변환을 시험하고, 입력 항목과 서식 칸을 짝지은 대응표를 만든다.
1. 공통 데이터 구조, 계산·검증, 테스트
2. ② 생성 → 한글로 확인
3. ① 생성 → 한글로 확인
4. ③ 생성 → 한글로 확인
5. 입력·검토·다운로드 화면
6. 지도
7. 배포
8. 전체 흐름 점검

한글 확인은 Claude가 화면 제어로 노트북의 한글에서 직접 연다. 열 때마다 사용자 허락을 받는다.

| HWP → HWPX 변환 중 내용이 빠짐 | 변환 보고서 확인. 문제가 있으면 노트북 한글에서 "다른 이름으로 저장 → HWPX"로 템플릿을 만든다 |
| 서식 기재 규칙이 지자체 실무와 다름 | 규칙 파일로 분리, 화면에 "가정" 표시 |
| 시연장 인터넷 문제 | 노트북 로컬 실행으로 대체 (서식 생성은 인터넷 없이 동작) |
| 큰 첨부 파일로 무료 서버 메모리 부족 | 합계 20MB·30개로 제한, 요청 크기 25MB에서 차단, 저장하지 않음 |

## 15. 심사 기준 대응 (발표용 메모)

- **지역 특성 반영도·활용 적합성 (40점)**: 경남 남해안 가두리 양식의 반복적인 고수온 피해를 대상으로 하고, 통영 시나리오와 가두리 단위 피해 지도로 보여 준다.
- **창의성 (20점)**: 서식 3종에 공통인 값을 한 번만 입력하게 하고, 놓치기 쉬운 법령 조건(지체 없이 신고, 재난 전 입식 신고, 10일 기한)을 자동으로 경고하며, 어업인 칸과 공무원 칸을 구분한다.
- **완성도 (20점)**: 공식 원본 서식을 그대로 보존한 HWPX를 만들고, 한글에서 직접 열어 확인한다.
- **주제적합성 (10점)**: 공식 서식(HWP) 자동 생성, 규칙 기반 검증, 가두리 피해 지도를 디지털 기술로 구현한다.
